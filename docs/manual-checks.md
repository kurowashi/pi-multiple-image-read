# 手動確認 — pi-multiple-image-read

自動検証の対象外の確認項目と手順です。

## 手動確認項目

前提: 画像対応モデルで Pi を起動します。日本語の確認には、Noto Sans CJK JP をインストールした環境を使います。

1. 12枚以上の PNG を含むディレクトリを `read_images` に渡し、TUI に複数のシートが表示されること。返答テキストの位置番号が、シートの左から右、上から下の順と一致すること。
2. 日本語のファイル名を含むディレクトリで、シート上のラベルが日本語で描かれていること。
3. Noto Sans CJK JP を削除した（または `DISABLE_SYSTEM_FONTS_LOAD=1` で Pi を起動した）環境で、日本語のファイル名が `(label not drawn)` になり、返答に「No Japanese-capable font」の注記が出ること。
4. 49枚以上の glob を渡すと、件数を示すエラーになり、セッションが続くこと。
5. 4000×40 px などの極端に細長い画像を含めると、`hard to read` の注記が出ること。
6. 壊れた PNG を1枚含めると、そのファイル名を示すエラーになり、他の画像は返らないこと。
7. モデルが、12枚のシートでラベルとタイルの対応を読めるか。次の観点で、実際の会話で確認します。
   - ファイル名の判読（ASCII、日本語）
   - 元のパスへの照合（位置番号）
   - 細部の見え方（小さな文字は読めないことがある、と分かるか）

## 寄与の測定（DESIGN.md の拡張の条件）

現在の 12枚 / シート、48枚 / 回の数値は、次の測定で見直します。

1. 同じ画像 N 枚（例: 12枚）を、(a) `read` を N 回、(b) `read_images` を1回で見せる。
2. 各リクエストの画像トークン（Pi の usage 表示または API の usage）を記録する。
3. 結果を、枚数・画像の大きさ別に表にして、DESIGN.md の拡張の条件に記録する。
