# ADR 0007: 一致しない入力は返答に列挙して残りを返す。全入力が0件のときだけエラーにする

## 状況

- 初版は、入力のどれか1つでも一致しない（0件の glob、存在しないパス、画像のないディレクトリ）と、呼び出し全体を失敗させていました。
- 例: `["./*.png", "./*.jpg", "./*.jpeg"]` で JPEG が1枚もないと、PNG が何枚あっても `no images match` で失敗しました。
- 復号失敗の扱い（[ADR 0004](0004-skip-unreadable-and-keep-label-end.md)）と食い違っていました。ADR 0004 は「1件の失敗で残りを返せなくなるのは利用者の要求に合わない」としています。

## 決定

1. 入力1件が画像に一致しないときは、その入力を `skipped: <input> (<reason>)` として返答に列挙し、残りの入力の画像は返します。
   - glob（画像が0件）: `no image matches`
   - ディレクトリ（画像が0件）: `no images in directory`
   - 存在しないパス: `not found`
2. 全入力が画像を1枚も返さないときだけ、呼び出しを失敗させます。エラーには各入力の理由を並べます（`no readable images; skipped: ...`）。
3. 明示指定した画像の形式が対応外（`unsupported image type`）は、従来どおり失敗させます。入力の種類を取り違えた明確な誤りだからです。

## 理由

- 拡張子ごとの glob を並べるのは、形式を網羅する自然な書き方です。その一部が0件なだけで全体が失敗すると、モデルは glob を組み直すしかなく、上限の目的（コンテキストを守る）とも合いません。
- 列挙すれば、一致しなかった入力は返答に見えます。黙って消えることはありません（[ADR 0004](0004-skip-unreadable-and-keep-label-end.md) と同じ扱い）。

## 却下した代替

- **0件の入力も全体の失敗にする（初版）**: 上の例のとおり、形式の網羅で失敗するため却下。
- **存在しない明示パスだけ失敗させ、glob の0件は注記する**: 誤字のパスが1つあるだけで全体が失敗します。一方、列挙すれば誤字も返答に見えるため、この区別は要りませんでした。却下。
- **0件の入力を黙って除外する**: 入力を間違えたことに気づけなくなるため却下。

## 未検証の点

- モデルが `skipped` 行を見て glob を直すかは測っていません。

## 帰結

- `expandInputs`（`src/files.ts`）は、一致しない入力で例外を投げず `skipped` を返します。`test/unit/files.test.ts` と `test/integration/read-images.test.ts` で固定します。
- 明示指定の対応外形式の失敗は変わりません。
