# ADR 0008: ラベルに入力順の番号を描き、返答テキストは全画像の番号とパスを列挙する。配置は面積が揃うスライス構造にする

## 状態

有効。[ADR 0003](0003-text-lists-only-unlabelled-images.md) の返答テキストの規則を置き換えます。

## 状況

- 初版から、シートは行ごとに高さを揃え、タイルを入力順に左から右、上から下へ並べていました。
- 入力順の位置は、返答テキストの `位置. パス` で示していました。モデルは、位置を「左上から何番目」と読みます。
- 実例7枚（縦横比が 0.43〜1.5）では、シート内の専有面積が最小 6.1% から最大 22.1% まで、約3.6倍の差がありました。
- 多画像の VLM は、画像の位置や入力順で答えが変わることが報告されています（Tian et al., CVPR 2025, "Identifying and Mitigating Position Bias of Multi-image VLMs"）。本プラグインでは、この報告を再測定していません。

## 決定

1. 番号は入力順の1始まりの通し番号とし、ラベルに `番号 ファイル名` の形で描きます。番号はシートの配置順と独立です。
2. 返答テキストは、ラベルの有無にかかわらず、全画像の `番号. パス` を番号順に列挙します。切れた・描けない・同名で共有されている画像には注記を付けます。
3. シートの配置は、各画像の面積を揃えるスライス構造（分割木）で決めます。余白は作らず、縦横比は保ちます。探索は固定シードの焼きなましで、同じ入力には同じ配置を返します。
4. ラベルの番号と返答テキストの番号は、ページをまたいで同じ値にします。

## 理由

- 番号は、位置の曖昧な表現（「左上から何番目」）を避け、ラベル上で画像と直接結びつけます。ラベルの番号と返答の番号が一致すれば、配置を読む必要がありません。
- 番号を配置順と独立にすると、配置を面積に合わせて自由に決められます。入力順を配置で保つ理由は、モデルの理解が配置に依存するかどうかに掛かっています。依存するなら、番号で対応を補います。
- 返答テキストを毎回全件にするのは、切れたラベルを持つ画像の元パスを確実に示すためです。ラベルで識別できる画像も含むため、[ADR 0003](0003-text-lists-only-unlabelled-images.md) のコスト（最大 18%）は残ります。確実性を優先します。
- 面積を揃えるのは、小さく写る画像が読めなくなるのを防ぐためです。実例7枚での面積比は、行ごとの配置が 3.6、スライス構造が 1.4〜2.1 です（同じ入力で、固定シードの探索を比較）。

## 却下した代替

- **入力順で配置し、位置を返答に書く（ADR 0003 の方式）**: 専有面積の差が約3.6倍のまま残るため却下。位置の表現も「何番目」と曖昧です。
- **行の高さを揃え、各行の幅を面積で決める**: 面積比は1.0まで改善しますが、余白が約31%出るため却下。
- **順番を保ったままのスライス構造**: 面積比は 1.5 前後で、順番を自由にした場合（約1.4）より大きいです。番号で対応を取るため、順番を保つ理由がありません。
- **番号を描かず、返答で位置だけを示す**: 位置は配置の読み取りに依存します（上記）。番号をラベルに描くと、返答と画像を照合する手間が減ります。
- **サイズの項を入れない面積のみの探索**: 細い縦一列の配置が、面積比の点で最良になります（全タイルが 116 px 幅の列）。タイルの大きさの項を入れて防ぎます。

## 未検証の点

- モデルが、番号と配置の対応を正しく読むかは、実際のモデルでは測定していません（`docs/manual-checks.md` の項目 7）。
- 面積の項の重み（0.5）は、実例7枚と合成の24枚で決めました。他の入力で、タイルが小さくなりすぎないかは未検証です。

## 帰結

- 番号、返答テキストの形式、配置を変えるときは、この ADR と `test/integration/read-images.test.ts` を同じコミットで更新します。
- シートの並びは入力順と一致しません。利用者向けの説明では、番号が入力順であることを示します。
