# ADR 0004: 読めないファイルは残りを返して列挙し、長いラベルは末尾を残す。48枚を超える入力はページングする

## 状況

- 初版は、1枚でも復号に失敗すると全体を失敗させていました。ラベルと位置がずれないことが理由でしたが、無関係な画像まで返せなくなっていました。
- ディレクトリと glob の TIFF は黙って除外していました。承認時の文言は「黙って除外せず、一覧に理由を出す」でした。
- ラベルは先頭から切っていました。1280×800 の画像 12 枚で測ると、次のとおりでした。

| ファイル名の形式 | 切れた数（12枚中） |
|---|---|
| `shot_01.png` | 0 |
| `Screenshot 2025-03-14 at 10.23.45 01.png` | 0 |
| `IMG_20250314_102345_01.jpg` | 0 |
| `スクリーンショット 2025-03-14 10.23.45 01.png` | 6 |

先頭から切ると、連番の末尾（`01`）が消えて、同系統のファイルを区別できません。

## 決定

1. 復号に失敗したファイルは、シートに載せず、返答に `skipped: <path> (cannot decode: <reason>)` と列挙します。残りの画像は返します。全件が失敗したときだけエラーにします。
2. ディレクトリと glob の中の TIFF は、`skipped: <path> (unsupported image type)` と列挙します。画像でないファイル（テキストなど）は、従来どおり黙って除外します。
3. ラベルが長すぎるときは、先頭と末尾を残して中央を `…` で省きます。
4. ラベルは、復号の成否に関係なく入力全体で決めます。ある画像が読めなくても、別の画像のラベルは変わりません。
5. 1回で返すのは48枚までです。超える入力は、`offset` 引数で次の呼び出しに回します。返答には「Showing inputs 1-48 of N. For the rest, call again with offset 48.」を出します。範囲は入力の数で、読めなかったファイルがあると返した画像の数より大きくなります。範囲外の offset はエラーです。

## 理由

- 1枚の失敗で他の画像を返せなくなるのは、利用者の要求に合いません。失敗は一覧で見えるので、黙って消えることもありません。
- 承認時の文言（TIFF を黙って除外しない）に合わせます。
- 末尾は連番の区別に使われるため、先頭より末尾を残すほうが識別に役立ちます。上の表は、12枚の範囲で先頭切りの欠点を示しています。

## 却下した代替

- **48枚超えをエラーにして絞り込みを求める（初版）**: 絞り込みには、モデルがファイル名を列挙する必要があります。その列挙がコンテキストを使い、上限の目的（コンテキストを守る）と逆になるため却下。
- **超過分を黙って切り捨てる**: 残りの画像に到達できず、見えないことに気づけないため却下。

- **全体を失敗させる（初版）**: 無関係な画像を返せなくなるため却下。
- **読めないファイルを黙って除外**: 原因が分からなくなるため却下。
- **先頭を残す**: 連番が区別できないため却下。
- **中央ではなく末尾だけを残す**: 先頭の語（撮影元など）が消えるため却下。

## 未検証の点

- モデルが `offset` を正しく使い、続きを読むかは実機で確かめていません（`docs/manual-checks.md`）。

- 中央省略で、モデルが実際にファイルを区別できるかは測っていません。手動確認の項目 7 で扱います。
- 切れたラベルの数の実測は、12枚の 1 形式だけです。枚数や名前の長さを変えた測定はしていません。

## 帰結

- 返答テキストの形式（`skipped` 行）を変えるときは、この ADR と `test/integration/read-images.test.ts` を同じコミットで更新します。
- 1枚の失敗で全体が落ちなくなったため、復号失敗の扱いは `test/integration/read-images.test.ts` の 3 件（残りを返す、TIFF を列挙、全件失敗）で固定します。
- ページングの仕様（境界、続きの案内、範囲外の offset、ページ間でのラベル）は `test/integration/read-images.test.ts` の 3 件で固定します。
- 「引数を増やさない」は、この ADR で取り下げました。上限超過時に名前の列挙を強いる欠陥を招いていたためです。
